## Godot-SQLite Addon

**Addon**: `addons/godot-sqlite/` — GDNative SQLite3 wrapper for Godot 4.0+
**Platforms**: Windows, Linux, Mac, Android, iOS, HTML5

### Core API (class `SQLite`)
```gdscript
var db := SQLite.new()
db.path = "res://data/game.db"       # read-only (packaged)
db.path = "user://data/game.db"      # read-write (runtime)
db.open_db()
db.close_db()
db.query("SELECT * FROM pilots")
db.query_with_bindings("SELECT * FROM pilots WHERE role = ?", [role_id])
db.create_table("pilots", { "id": {"data_type":"int","primary_key":true}, ... })
db.insert_row("pilots", {"id":1, "role":"Tank", "hp":200, "atk":8})
db.select_rows("pilots", "hp > 100", ["role","hp"])  # returns Array of Dicts
db.update_rows("pilots", "id = 1", {"hp": 210})
db.delete_rows("pilots", "id = 1")
```

### Data Types
`int` → INTEGER, `real` → REAL, `text`/`char(n)` → TEXT, `blob` → BLOB (PackedByteArray)

### Important Constraints
- Column/table **names cannot be bound** — interpolate them directly into query strings
- **No encryption** support
- Read-only DBs: package inside `.pck` at `res://`; Read-write DBs: copy to `user://` at runtime
- Foreign keys must be enabled **before** `open_db()`

### Import / Export
```gdscript
db.export_to_json("user://backup.json")
db.import_from_json("res://data/seed.json")
db.backup_to("user://save.db")
db.restore_from("user://save.db")
```

### CSV → DB Workflow Pattern
CSV files live in `data/csv/`. The conversion logic lives in
`addons/csv_to_db/csv_to_db.gd` (a plain `RefCounted`); `addons/csv_to_db/plugin.gd`
is a thin **EditorPlugin** that only registers the menu item
(**Project → Tools → Rebuild game.db**). It reads each CSV, validates required
columns + duplicate PKs, then writes `res://data/game.db` with
`create_table` + `insert_row`. Adding a new table = add a CSV under `data/csv/`
and add an entry to both `SCHEMAS` and `TABLE_DEFS` **in `csv_to_db.gd`**.

The logic sits outside the EditorPlugin because `EditorPlugin` cannot be
instantiated headlessly, so the DB can also be rebuilt from the CLI:
```gdscript
# a throwaway `extends SceneTree` script, run with --headless --script
func _initialize() -> void:
    var err: String = load("res://addons/csv_to_db/csv_to_db.gd").new().call("rebuild")
    if err != "": printerr(err)
    quit()
```

### Tables (current)
| Table | CSV | Read at | Purpose |
|---|---|---|---|
| `pilots` | `pilots.csv` | BattleSim startup | Per-role baseline stats (used as fallback when match_ctx is inactive) |
| `cards` | `cards.csv` | GameManager startup | **Pilot (파일럿) card table (43 rows) — all `card_type = pilot`.** The former "shared mech cards" (mech rows) are gone; mech (메크) cards live only in `mech_cards`. `scope` is a **position list** — `any` alone = all, `lane` alone = top/mid/carry/support, otherwise `jungle`/`top`/`mid`/`carry`/`support` joined with `\|`. `card_cat` is a **category** field holding several values joined with `\|` (growth/engage/ambush/attack/defense/utility/draw/jungle/lane, `-` for grant-only), and `pilot_card_slots` slots pick candidates by this value. `pool` (1/0) — 0 means not a pilot card candidate (결투 (Duel) · 전령 제압 (Herald Subdued) · 용 보상 (Dragon Reward) · 핫핸드 (Hot Hand) · 이동 (Move)). `keyword` is a `\|` list (`exhaust` / `preserve` / `volatile` / `charge` / **`reposition`** = reposition, move to the far left of the hand (손패)) — **keywords are not repeated in the description text** (the description panel draws the keyword line and its explanation separately). A **`charge_max`** column was added (Charge (충전) cap; 성장 가속 (Growth Acceleration) uses it). `excl_group` is currently used by no card. Description terms: **손** (hand; ← 손패 · 핸드) · **소지 중** (while held; ← "while in hand") · **찾기** (search; ← 탐색) · **버린 더미** (discard pile; ← 묘지) · **뽑기** (draw; ← 드로우) · **턴** (turn; ← 라운드 (round)) · **토큰** (token — what Charge fills) · **작전 단계** (operation phase) · **교전** (engage). **Deleted ids (4 · 10 · 20) are not reused** — new cards get the next id at the end. Notation rules: the "설명문 표기" (description notation) section of `features/battle_sim/card_phase/README.md`; card list and rename history: the cards.csv column section of the same README. |
| `game_config` | `game_config.csv` | BattleSim startup | Tunable knobs (HP, turns, thresholds) — a separate table from `const`, read by BattleSim's `DataLoader`. Values live only in the CSV; this row names keys, never values. `MAX_HAND_SIZE` is the hand cap; `BLUE_COST_HEAD_START` is the strategy points the blue side gets as a head start. **`INITIAL_HAND_SIZE` was deleted** — the opening hand (개시 손패) is gone and both teams start with empty hands. `ECONOMY_START_TURN` is the turn when strategy point recovery / auto-draw first runs. **`GROWTH_PER_TURN` was deleted** — growth (성장) is now derived from growth points (성장치), not time, so the concept of a per-turn growth rate disappeared (see the "Growth" item in `features/battle_sim/README.md` "Active Systems"). Instead `PILOT_STRUCTURE_DMG` was added — the **fixed** damage a pilot deals to a turret (포탑)/HQ per hit, independent of `atk`. `BATTLE_PILOT_DMG_MULT` multiplies only **damage dealt to pilots by battlefield (전장) combat** — turret/HQ damage · attack cards · the engage stage (교전 무대) are excluded. `TURRET_HP` and `HQ_MAX_HP` are tuned against `PILOT_STRUCTURE_DMG`, so tweaking the three separately breaks siege speed — change them together. A turret's growth point value is `SCORE_TURRET_FULL` (const.csv) regardless of `TURRET_HP`, so raising `TURRET_HP` only lowers the per-point value. `TURRET_SPEED` was **deleted** — engage became round-based turns, so participating turrets also fire once per round and there is no speed concept. Return-to-base (복귀) is now instant full HP + 1 turn wait, so there are no heal/wait keys — both `RECALL_HEAL_RATIO` and `RECALL_RETURN_TURNS` were removed. For the seven objective knobs (`OBJ_HERALD_FIRST_TURN` / `OBJ_DRAGON_FIRST_TURN` — Dragon (용) comes first / `OBJ_RESPAWN_TURNS` / `OBJ_RETRY_TURNS` / `OBJ_ENGAGE_ROUNDS` / `OBJ_DRAGON_CARD_COUNT`) see `objective/README.md`. **`OBJ_DRAGON_GROWTH_PCT` and `OBJ_HERALD_TURRET_DMG` were deleted** — the Herald damage comes only from the [전령 제압] card's `turret_damage` clause (cards.csv), and Dragon growth now comes only from the [용 보상] (Dragon Reward) card's `growth_perm` clause in `cards.csv`. The Dragon reward was lowered from its old values because Dragon opens more than three times, so the old values dominated the whole late-game growth points curve. |
| `const` | `const.csv` | Lazily, on first access via `ConstTable` (`resources/ConstTable.gd`) | **Gameplay tuning constants moved out of scripts.** Columns `key` / `value` / `module` (the consuming script) / `note`. Key families: engage stage pace & targeting `ENGAGE_*`, pilot skill multipliers `SKILL_*`, mech passive multipliers `MECH_*`, growth-point economy `SCORE_*` / `GROWTH_*` / `JUNGLE_CAMP_*`, AI card weights `AI_CARD_*`, card effects `CARD_*`, objective AI `OBJ_*`, training `TRAINING_*`, hit range `PILOT_HIT_*`, player stat `PLAYER_*`. Scripts keep the old const name as a `static var` initialised from `ConstTable.num(...)` / `int_of(...)`, so callers are unchanged. **Rule: change a value only in the CSV, then run Rebuild game.db** — never in a script. READMEs and code comments name the key, never its value (a value written in two places always ends up lying in one). `game_config` stays a separate table. |
| `lane_config` | `lane_config.csv` | BattleSim startup | LANE_NAMES, LANE_MAX, midpoints |
| `pilot_skills` | `pilot_skills.csv` | GameManager startup | **25 pilot skill rows** — 5 per role. `key` is the runtime branch key (1:1 with `PilotSkillSystem.KEY_*`), `type` is `cooldown`/`charge`/`passive`, `p1` is the cooldown in turns or the activation Charge cost, `p2` is the max Charge. Multipliers (what %) are not columns here — to avoid creating five or six number columns whose meaning differs per skill — they live in `const.csv` under `SKILL_*` keys (read by `PilotSkillSystem`). `description` writes line breaks as the two characters `\n` like cards, card names as `[card name]`, and Korean particles as tags (`{eul}` 을/를 · `{eun}` · `{i}` · `{wa}`) resolved by `StrategyIcon.resolve_josa`. Full list and notation rules: `features/battle_sim/skill/README.md`. |
| `players` | `players.csv` | Season + MatchFlow startup | 40 pilots (8 teams × 5 roles), `PlayerData` fields. **There are six stat columns** — `field_hit` / `field_eva` / `engage_hit` / `engage_eva` / `atk_growth` / `hp_growth` (see the "Player stats (six)" item in `features/battle_sim/combat/README.md` "Active Systems"). The old five (`laning`/`mechanics`/`gamesense`/`teamfight`/`mental`) were deleted. **Supports (role 3) lean toward `field_eva`, carries (role 4) toward `field_hit`** (totals unchanged, 10 points shifted each way) — the bot-lane bond pair shares battlefield hit / evasion as an average (`combat/README.md` "Lane bond"), so together they balance like a solo laner, and when one drops out the other's skew shows. `intl_players` follows the same rule. **`skill_id`** points to `pilot_skills.id` (-1 = none), and **`is_mob`** means silhouette portrait · no skill · excluded from draft all at once — the 25 named players are spread evenly over the 8 teams (team 0 has 5, the other 20 are 2–3 each across 7 teams), and the 15 mob pilots' stats are already lower in the CSV values themselves. Player drafts 5 from this pool in Season. **`name` is bound to that id's portrait** — which Zenless Zone Zero agent `resources/images/pilot/*/N+1_*.png` (used by pilot id `N`) shows is the name (all 40 checked against the official icon art). Changing row order·ids desyncs names and faces — detailed rules and the 4 alternate costumes: the `PilotImages.gd` section of `resources/README.md`. A **`pilot_cards`** column was added — this player's **3 fixed pilot cards** (`cards.id` joined with `\|`). Current values were filled by one roll through `pilot_card_slots`; if the cell is empty, `GameManager.pilot_card_ids_for` rolls deterministically using the player id as seed. Ids blocked by the position or nonexistent ids are dropped and missing slots are filled by the seeded roll. |
| `mechs` | `mechs.csv` | MatchFlow startup | **21 mech pool** (원딜 (ADC) 5 · 전사 (Warrior) 4 · 탱커 (Tank) 3 · 지원 (Support) 5 · 암살 (Assassin) 4). 9 were removed from the old 30 and **surviving ids were left unchanged** — `resources/images/mech/{id}_full.png` is bound to the id, so renumbering would desync art and stats wholesale; hence the id gaps (3·4·5 / 10·11 / 16·17 / 23 / 29 are missing). **A `role` column was added** (GameEnums.Role) — because each mech got its own card set and those cards assume a role class; assignment still doesn't restrict which mech sits in which slot. Only Barrage (id 27) had its attack lowered (the price of its full-salvo passive). Drives PilotData stats when picked. **`id` is bound to the full-body art** — `resources/images/mech/{id}_full.png` is laid out to match that id's stat archetype (Tank 0–5 / Brawler 6–11 / Assassin 12–17 / Supporter 18–23 / Sniper 24–29), so changing row order or stat ranges desyncs art and stats — see the mapping table in `resources/README.md`. `name` is our own naming unrelated to the art, and **all 21 are unique English-word codenames** (Juggernaut · Overdrive · Barrage …) — the old `계열-A1` / `-A2` (series-A1 / -A2) suffix names (same series differing only by number, like Bulwark-A1 / Bulwark-A2) were replaced. | `mech_passives` | `mech_passives.csv` | GameManager startup | **15 mech passive rows** — only 15 of the 21 mechs have one. `mech_id` is the pairing and `key` is the runtime branch key (1:1 with `MechSkillSystem.KEY_*`); `p1`/`p2` are two numbers whose meaning differs per passive (starting Charge · max Charge · vulnerability amount · damage ratio). | `mech_cards` | `mech_cards.csv` | GameManager startup | **64 mech card rows** — wholly replaces the "3 mech cards" a pilot receives. `count` is how many copies enter the deck when the mech is picked, and **the six with `count = 0`** (승전보 (Victory Report) · 철거 (Demolish) · 처형 (Execute) · 락온 (Lock-on) · 고통과 쾌감 (Pain and Pleasure) · 단계 B/C (Stage B/C)) only come into existence when a passive or another card creates them (they are still listed in the allocation table — so the detail panel's mech tab doesn't show only half the mech). **`cost = -1` means unplayable**. **`charge`** was added to `keyword`, a **`charge_max`** column was added (Charge cap, 0 if not a Charge card), and three were added to `target` — `foe` (enemy pilot **or** turret → targeting picks a **cell**, and the attack clause decides what in that cell is hit; turrets have no portrait, so the PILOT overlay can't be used) / `turret_outer` / `turret_any`. At runtime, `GameManager` and BattleSim's `DataLoader` open the DB once, load
tables into Dictionaries / Arrays keyed by ID, then close the DB. All in-game
access goes through those structures — not live DB queries.
