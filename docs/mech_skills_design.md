## 0. 한 줄 요약

**파일럿 스킬이 선수에게 붙는 한 수라면, 메크 스킬은 기체가 하는 일이다.**
밴픽에서 기체를 고르는 순간 그 파일럿의 덱 절반과 상시 능력 하나가 함께 정해진다.

예전에는 `cards.csv` 의 `card_type = mech` 카드 풀에서 아무거나 3장을 뽑아 줬다 —
기체는 hp / atk / presence 숫자 세 개일 뿐이었고, 어느 기체를 골라도 나오는 카드가
같았다. 지금은 **기체마다 자기 카드 셋과 자기 패시브**가 있고, 카드 장수도
기체마다 다르다(2~7장). 그 장수 차이 자체가 기체 선택의 일부다.

## 2. 신규 키워드 넷

### 2.1 충전 (`charge`)

> 이 카드가 **내 핸드에 들어올 때마다 충전 +1**(상한 `charge_max`). **사용 시 모든
> 충전을 소모**하고, 소모한 수만큼 효과가 세진다.

세기가 카드 **한 장의 상태**(`CardData.charge`)로 사는 것이 요점이다. 그래서
`count = 1` 로 족하고, 더미로 내려갈 때 흩을 것도 없다.

- 오르는 자리는 둘뿐 — `CardPhaseManager.add_card_to_hand` / `draw_card`. 둘 다
  `CardData.gain_charge()` 를 지나므로 상한 판정이 한 군데에만 산다.
- 태우는 자리는 하나 — `CardPhaseManager._burn_charge(cd)`. 카드가 손을 떠날 때
  한 번 돌고, 태운 수를 `_charge_spent` 에 적어 둔다(효과 체인은 오버레이 때문에
  여러 프레임에 걸쳐 돌 수 있어서, 그 시점의 `charge` 는 이미 0 이다).

| 충전 카드 | 상한 | 충전이 하는 일 |
|---|---|---|
| 미사일 (C) | 3 | 사거리 2 내 **타일**을 지정 — 그 타일의 **모든 적**을 충전 수만큼 |
| 전장 강타 (I) | 5 | **충전 수 + 1** 명의 무작위 적을 하나씩 |
| 약자 멸시 (R) | 3 | 핸드 상주 — 교전을 시작하면 충전 수만큼 최저 HP 적을 공격력 50% 로 |

> **예전에는 `스택` 이었다.** 같은 카드가 손패에서 한 장으로 뭉치고
> `CardData.stack_count` 가 장수를 들었다. 손패 크기 · 상한 정리 · 부채꼴 · 히트
> 밴드를 손대지 않아도 된다는 장점은 있었지만, 더미로 내려갈 때마다 낱장으로 다시
> 흩어야 했고(안 그러면 리셔플 한 번에 덱 장수가 준다) 세기의 상한이 곧 `count` 라
> 카드 한 종류가 덱을 3~5장씩 불렸다. **공격 명령(K)** 은 이 전환에서 충전을 버리고
> `death_hand` 훅(처치마다 손패에 한 장 생성 · `소멸`)으로 갔다.

### 2.2 count

> 채용 시 덱에 들어가는 카드 수. `count = 0` 이면 별도 효과로 생성되지 않는 한 만날 수 없다.

`count = 0` 인 카드 여섯 장(승전보 · 철거 · 처형 · 락온 · 고통과 쾌감 · 단계 B/C)은
패시브나 다른 카드가 만들어 줄 때만 세상에 나온다. **그래도 배분 표
(`BattleSim.starter_cards`)에는 적는다** — 상세 패널의 메크 탭이 "이 기체가 무엇을
하는 기체인가"를 보여 주는 자리라, 조건부로만 나오는 카드가 거기서 빠지면 기체를
반만 읽게 된다.

### 2.3 코스트 -1 (사용할 수 없음)

> 낼 수 없다. 핸드에 있는 것만으로 효과를 주거나, 특별한 방법으로만 쓰인다.

네 장이 쓴다 — **캐시**(B) · **계시**(I) · **약자 멸시**(R) · **밸런스**(U).
비용 칸에 숫자 대신 `—` 가 찍히고, 지불 불가로 잠겨 슬래브가 덮이며, 드래그도
거부된다. **단 버리기 픽 중에는 끌린다**: 못 내는 카드라고 못 버리는 것은 아니다.

0 코스트와 헷갈리지 말 것 — 0 은 공짜로 낼 수 있다는 뜻이고 -1 은 낼 수 없다는 뜻이다.

효과 문법은 `hand_passive:<key>` 한 줄뿐이고, 실제 동작은 `MechSkillSystem` 이
손패를 훑어 직접 읽는다(절 문법을 태울 수 없다 — 절은 카드가 나갈 때 도는 것이므로).

### 2.4 휘발성 (`volatile`)

> 사용하지 않고 버려지면 버린 더미로 가지 않고 제거된다.

**이미 있던 키워드다** — 파일럿 스킬이 손패에 만들어 주는 카드들이 쓰고 있었고,
메크 쪽에서는 **철거**(F) · **락온**(J), 그리고 정밀 폭격이 만드는 임시 미사일이 쓴다.

소멸(`exhaust`)과 짝이지만 같은 것이 아니다 — 소멸은 **쓰면** 사라지고 휘발성은
**안 쓰고 버려지면** 사라진다. 둘을 함께 달면 그 카드는 어느 쪽으로도 덱을 불리지 않는다.

## 3. 덱 구성이 바뀐 자리

| | 예전 | 지금 |
|---|---|---|
| 메크 카드 | 공용 풀에서 **3장 뽑기** | **배정된 기체의 카드 전부**를 `count` 만큼 펼침 (2~7장) |
| 파일럿 카드 | 3장 (역할별 슬롯) | 그대로 |
| 팀 덱 크기 | 5 × 6 = **30장 고정** | **25 ~ 43장** (메크 조합이 정한다) |

`MECH_CARDS_PER_PILOT`(3) 는 **폴백 상수로만 남았다** — `match_ctx` 없이
`BattleSim.tscn` 을 직접 돌려 배정된 기체가 없을 때만 예전 경로를 탄다.

이론 하한은 메크 카드가 2장뿐인 기체(H · J)로만 채운 25장, 상한은 가장 두꺼운
다섯(I 7 · R 6 · A/C/T 5)을 모은 43장이다. 실측(헤드리스, 역할군 회전 5회):
**30 / 33 / 35장**.

## 4. 효과 문법 — 새로 생긴 절

기존 절(`draw` / `discard` / `strategy` / `attack` / `engage` / `move` / `shield_pct` …)은
그대로이고, 아래가 메크 카드만 쓰는 절이다. **이름을 공용 절과 겹치지 않게 지은 것은
의도된 것**으로, 카드 한 장의 `effect` 문자열만 보고도 "이건 기체가 주는 카드"임이
읽혀야 하기 때문이다.

### 4.1 체인 제어

| 절 | 뜻 |
|---|---|
| `on_hit` | 앞선 공격 절이 **한 대라도 맞았으면** 이후 절을 실행 |
| `on_miss` | 전부 빗나갔으면 이후 절을 실행 |

절 하나에 조건을 매다는 대신 체인을 두 토막으로 자른다 — 카드가 요구하는 문장이
언제나 "명중 시 A, 빗나갈 시 B" 두 갈래이고, 갈래마다 절이 여럿이기 때문이다.

> 간보기: `attack:1;on_hit;engage:3|at_target;on_miss;strategy:4`

### 4.2 공격 절의 새 플래그

`attack:N` 은 여전히 "적 하나를 N × ATK 로 한 번"이 기본형이고, 플래그가 대상 집합을
넓힌다. 대상은 **PilotData 이거나 TurretData** 이며, 둘을 가르는 자리는 피해를 넣는
두 함수뿐이다(명중 판정 · 돌진 연출 · 팝업은 공유).

| 플래그 | 대상 | 쓰는 카드 |
|---|---|---|
| `all` | 전장 내 모든 적 파일럿 | 천둥 폭풍 |
| `random` | 무작위 적 (`charge` 와 함께면 **충전 수 + 1** 명을 뽑는다) | 전장 강타 |
| `self_range:N` | 시전자 기준 N칸 내 적 + 포탑 | 테러 · 초고출력 · 영혼 포식 · 휩쓸기 · 즉발 베기 |
| `area:N` | 지정 대상 기준 N칸 내 적 + 포탑 | 정밀 폭격 · 파괴 |
| `damaged` | 이번 작전 단계에 이 메크가 때린 적 전부 | 락온 · 신속 |
| `line` | 아군 HQ ~ 지정 포탑까지의 레인 전부 | 꿰뚫는 번개 |
| `turret_only` | 지정한 적 포탑 하나 | 철거 |
| `charge` | **각 대상을** 충전 수만큼 반복 (`random` 과 함께면 대상 수를 정한다) | 미사일 · 전장 강타 |
| `pierce` / `repeat` | (기존) 필중 / 명중마다 반복 | |

**파일럿→포탑 카드 피해는 고정값**(`PILOT_STRUCTURE_DMG` = 2)이다. `atk` 비례로 두면
성장이 공격력을 ×3 까지 미는 후반에 카드 한 장이 포탑을 통째로 지운다 — 전장 공성이
고정 피해로 바뀐 것과 같은 이유다.

### 4.3 나머지 절

| 절 | 뜻 | 플래그 |
|---|---|---|
| `heal_pct:N` | 대상 최대 체력의 N% 회복 | `self` `per_hit` |
| `max_hp:N` | 최대 체력 **영구** +N | `self` `per_hit` |
| `atk_add:N` | 공격력 **영구** +N | `self` |
| `shield_atk:N` | **시전자 공격력의** N% 보호막 | `all_allies` |
| `reactive_armor:N` | 반응 장갑 N겹 | `self` `per_hit` |
| `charge:N` | 메크 패시브 충전 +N | `per_hit` |
| `score_cost:N` | 성장 점수 N 소모 (**N=100 이 1.00k**) | |
| `growth_eff:N` | 성장 적립 +N% (전장 이탈까지, 누적) | |
| `gen_hand:ID` / `gen_deck:ID` | 그 메크 카드를 만들어 손패 / 덱에 | `per_hit` `per_kill` `temp` |
| `search_card:ID` | 덱에서 그 카드를 찾아 손패로 | `count:N` |
| `search_discard:N` | 묘지 탐색 — 버린 더미를 **펼쳐 고른다** | |
| `draw_discard:N` | 묘지 드로우 — 위에서부터 N장 | `cost_reduce:N` |
| `push:N` | 밀기 N칸 | `bonus_clear:N` |
| `move_target:N` | **적을** N칸 민다 | |
| `move_to_target` | 시전자가 대상 칸으로 뛰어든다 | |
| `pull_to_caster` | 적을 시전자 칸으로 끌어온다 | `self_range:N` |
| `mark_target:N` | 목표 — 시전자에게 받는 피해 +N% | |
| `track:N` | 추적 N턴 | |
| `link_engage` | 결속 | |
| `stun_next` | 강타 | |
| `no_engage_phase` | 탈진 | |
| `dmg_taken:N` | 받는 피해 +N% (중첩 없음) | |
| `bounty:N` | 현상금 = 대상 성장치의 N% | |
| `attack_bounty:N` | 현상금의 N% 를 피해로 | |
| `mutual_attack:N` | 서로 N번씩 (대상 쪽은 필중) | |
| `taunt_all` | 모든 적이 시전자를 필중 공격 | |

| `hand_passive:<key>` | 비용 -1 카드의 표지 (실행되지 않음) | |

### 4.4 교전 절의 새 플래그

| 플래그 | 뜻 | 쓰는 카드 |
|---|---|---|
| `at_target` | 지정한 **적 주변**에서 연다 | 돌격 · 강습 · 간보기 |
| `at_marked` | 목표가 찍힌 적 주변에서 | 단계 B |
| `self_range:N` | 시전자 중심 반경 N | 우세한 전장 3 · 개시 2 · 제압 전투 2 |
| `charge_rounds` | 라운드 수를 영혼 포식 충전으로 갈음 | 전쟁의 사슬 |

`EngagePhaseManager._gather_participants` 가 `center` / `radius` 를 받게 됐고, 기본값은
예전 그대로(시전자 칸 + 인접 6칸)다.

### 4.5 새 대상 종류 (`target` 컬럼)

| 값 | 뜻 |
|---|---|
| `foe` | 적 파일럿 **또는** 포탑. 대상 지정은 **칸**을 고르게 하고, 그 칸의 무엇을 때리는지는 공격 절이 정한다(파일럿이 먼저) |
| `turret_outer` | 레인별 최외곽 적 포탑 |
| `turret_any` | 살아 있는 적 포탑 전부 (사거리 무시) |
| `pilot` | 아군과 적을 **둘 다** 고를 수 있다 (매혹) |

`foe` 가 칸을 고르게 하는 이유: 대상 지정 오버레이는 초상화(PILOT)와 칸(LOCATION)
둘 중 하나만 다룰 수 있는데, 포탑에는 초상화가 없다.

## 5. 지속 상태 — `PilotData` 에 새로 산 필드

메크가 거는 상태는 전부 `PilotData` 에 살고 `MechSkillSystem` 이 켜고 끈다. 계산은
**원래 하던 자리**가 그대로 한다 — 스탯을 직접 밀면 성장 재계산 한 번에 지워지기
때문이고, 카드의 일시 공격력(`atk_buff`)이 따로 사는 것과 같은 이유다.

| 필드 | 뜻 | 읽는 자리 |
|---|---|---|
| `vulnerable` | 취약 — 1마다 받는 피해 +1% | `damage_taken_mult` |
| `reactive_armor` | 반응 장갑 — 한 대당 90% 감소 후 1 소모 | `consume_reactive_armor` |
| `damage_taken_bonus` | 받는 피해 배율 가산 (죽음의 손가락) | `damage_taken_mult` |
| `bounty` | 현상금 | `attack_bounty` |
| `marked_by` / `marked_bonus` | 목표 (그 시전자에게만) | `damage_taken_mult` |
| `tracked_by` | 추적 — 이 적이 싸우면 끌려 들어올 사람들 | `_gather_participants` |
| `engage_link` | 결속 | `_gather_participants` |
| `engage_locked` | 탈진 | `_gather_participants` |
| `stun_charge` / `stunned_rounds` | 강타 / 기절 | 교전 무대 (2단계) |
| `growth_link_to` | 매혹 | `BattleSim.add_score` |
| `bonus_atk_flat` / `bonus_atk_mult` / `bonus_max_hp` | 영구 스탯 보정 | `refresh_growth_stats` |
| `phase_return_cell` | 자리 되돌리기 예약 (질풍) | `MechSkillSystem.on_phase_end` |

**반응 장갑은 보호막보다 먼저 걸린다** — 90%를 깎고 남은 10%를 보호막이 받는 순서라야
두 방어가 겹쳐 읽힌다. 반대로 두면 보호막이 온전한 피해를 먼저 먹고 장갑은 잔량에만
걸려 사실상 아무 일도 하지 않는다.

**취약 · 죽음의 손가락 · 목표는 곱이 아니라 합이다.** 셋 다 "받는 피해 +N%"라는 같은
문장이고, 곱으로 쌓으면 취약 100 에 죽음의 손가락이 겹친 순간 배율이 2.5 를 넘어
한 대에 정리되는 구간이 생긴다.

## 7. 어디까지 서 있나

### 1단계 — 데이터와 절 문법

- 데이터 3종(`mechs` 21행 · `mech_passives` 15행 · `mech_cards` 64행)과 로더
- `MechSkillSystem` — 패시브 15개, 충전, 사건 훅 9개, 질의 함수
- 덱 구성이 기체를 따라감 (`count` 그대로)
- 신규 키워드 넷 (충전 · count · 코스트 -1 · 휘발성)
- 공격 절의 대상 집합 9종 + 포탑 대상 + 체인 제어(`on_hit`/`on_miss`)
- 위 4.3 절 표의 절 전부, 교전 절의 새 플래그 넷, 새 대상 종류 넷
- 취약 · 반응 장갑 · 목표 · 받는 피해 배율이 **전장 자동 교전과 카드 공격 양쪽**에 적용

### 2단계 — 교전 무대 · 단계 사슬 · AI

| 항목 | 어떻게 붙었나 |
|---|---|
| **기절 / 약자 멸시 / 전탄 발사 / 오버클럭 / 불굴** | 약자 멸시는 `setup` 의 `_contempt_opening`(1라운드 전 선제 타격), 나머지는 `TurnEngageSim` 이 네 자리에서 `MechSkillSystem` 의 질의 함수를 읽는다. `_resolve_attack` 이 **대상 집합을 정하고** `_strike_one` 이 그 하나하나를 굴리는 두 층으로 갈렸다 — 전탄 발사는 한 차례에 여러 대상, 오버클럭은 같은 대상에 여러 번이라 한 함수로는 표현되지 않는다. 기절은 순서 배열에서 빼지 않고 `_advance_order` 가 건너뛴다(살아 있는 사람들의 상대 순서를 지키기 위해). 불굴은 `_apply_damage` 에 있다 — **포탑 사격도 같은 함수를 지나므로** 파일럿 공격에만 걸면 포탑 한 방에 죽는 구멍이 남는다 |
| **수호 연계**(Q) | `shield_source` 를 읽는 `on_shielded_ally_damage` 하나. 카드 피해는 그 자리에서 부르지만 **전장 자동 교전은 적어만 두고**(`SimulationCore._guardian_rides`) 이번 턴의 피해가 전부 적용된 뒤 굴린다 — 판정 단계에서 곧장 때리면 편승 한 방이 아직 적용되지 않은 피해보다 먼저 상대를 눕혀, 같은 턴의 나머지 판정이 시체를 상대로 굴러간다. 게이트가 셋이다: 그 아군이 **지금도** 보호막을 두르고 있을 것, 편승하는 메크가 자기 자신이 아닐 것([수호]는 시전자에게도 건다), 재진입 금지(두 메크가 서로에게 걸면 고리가 닫힌다) |
| **단계 B / 단계 C 체인** | `phase_b` 는 바로 앞 `engage` 절의 결과를 읽고, `phase_c` 는 강화 3택을 고르게 한다. **그게 성립하려면 `engage` 절이 무대가 닫힐 때까지 기다려야 한다** — `_effect_engage` 가 `engage_finished` 를 await 하게 됐고, 교전 성적표는 무대가 치워진 뒤에도 답해야 하므로 `EngagePhaseManager._last_stats` 에 사본으로 남는다. 3택 UI 는 전용 모달을 새로 만들지 않고 `CardSelectOverlay` 에 `Mode.CHOICE` 를 더했다(찾기와 같은 그리드, **이름순 정렬 없음**, **취소 없음**) |
| **`per_kill` 로 세는 교전 처치** (우세한 전장) | 같은 await 하나가 함께 고쳤다. `_effect_engage` 가 돌아온 뒤 `_last_attack_kills` 에 이번 교전의 처치 수를 얹으므로, 뒤따르는 절은 절 종류를 몰라도 "방금 그것이 몇을 눕혔나"를 그대로 묻는다 |
| **질풍의 위치 복귀** | `PilotData.phase_return_cell` 예약 한 칸. `_effect_move_to_target` 이 뛰어들기 직전 칸을 적고 `MechSkillSystem.on_phase_end` 가 되돌린다. 사망 · 복귀는 `clear_field_effects` 가 예약을 지운다 — 그 둘은 이미 자리를 옮긴 뒤라, 되돌리면 방금 일어난 일을 무르는 꼴이 된다 |
| **AI 의 카드 사용 판단** | 무작위 픽이 **우선순위 점수제**로 바뀌었다(`AiCardPlayer._score_card`). 못 내는 카드와 **고를 대상이 없는 카드**를 먼저 빼고, 절 이름으로 점수를 매기고(카드가 절을 여럿 달았으면 가장 높은 절이 그 카드의 성격이다), 비용으로 감점하고, 동점은 흔들림으로 가른다. 여기서 **비용 -1 카드를 AI 가 태우던 버그**도 함께 잡혔다 — `effective_cost_for` 가 결과를 0 아래로 깎지 않아 "0 코스트"로 읽혔었다 |

### 아직 남은 것

| 항목 | 왜 |
|---|---|
| **강화 3택의 AI 판단** | AI 는 알파 · 베타 · 감마를 무작위로 고른다. 파일럿 스킬 쪽 AI 가 활성화를 아예 하지 않는 것과 같은 1차 한계이고, 고르는 규칙을 세우려면 "지금 이 사슬이 몇 바퀴째인가"를 AI 가 알아야 한다 |
| **기절의 라운드 길이** | 지금은 언제나 1라운드(다음 차례 하나)다. 카드 텍스트가 길이를 말하지 않아 최소값을 골랐다 |
