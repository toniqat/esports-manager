# Module: Engage (전투 개시) — 사이드뷰 벨트 교전 (ATB)

## Purpose
`engage:N` / `duel` 카드 효과로 발동되는 **실시간 교전**. 전장(BattleSim)이
셀 단위 턴제로 굴러가는 것과 달리, 교전은 전용 **사이드뷰 벨트스크롤 무대**
에서 각 파일럿이 자기 ATB 게이지를 굴리며 접근 / 공격을 연속 시간 위에서
수행한다. **플레이어 입력은 없다 — 관전 전용.**

> **교전 중 이탈은 없다.** 제한 시간이 끝날 때까지 아무도 무대를 뜨지 못한다.
> 빈사(HP<30%)여도 후퇴하지 않는다.

> **원위치 복귀도 없다.** 공격을 끝낸 유닛은 그 자리에 눌러앉고, 그 자리가
> 새 앵커(`anchor_pos`)가 된다. 그래서 교전이 길어질수록 양 팀이 서로에게
> 파고들어 무대 한쪽으로 뭉친다. 예전의 `RETURN`(진형 슬롯 복귀) 상태는
> 삭제됐다 — 되살리지 말 것.

> 2026-08 이전의 **탑뷰 아레나**(전장 육각 셀을 확대 매핑한 좌표계, 카이팅 /
> 포탑 사거리 회피 / 다이브 판정 / 개전 대쉬)는 제거되었다. 그 이전의 N 라운드
> 턴제 루프(`EngageOverlay.gd`)도 마찬가지. 둘 다 되살리지 말 것.

## Files
| File | Purpose |
|---|---|
| `EngagePhaseManager.gd` | `class_name EngagePhaseManager extends Node` — 오케스트레이터. 참가자를 모으고, `RealtimeEngageSim` 을 만들고, `_process` 에서 고정 스텝으로 굴리고, 종료 판정 후 `END_HOLD_SEC`(2.0초) 유예를 두고 대시보드를 띄운다. 공개 API는 예전과 동일: `start_engage(caster, rounds, exclude_lane, on_done)` / `start_duel(caster, target, on_done)` / `is_active()` / `engage_finished` 시그널. |
| `RealtimeEngageSim.gd` | `class_name RealtimeEngageSim extends RefCounted` — **헤드리스 시뮬레이터**. 노드를 하나도 만들지 않는다. 벨트 좌표, 진형 배치, ATB, 유닛 행동 사이클, 포탑, 데미지, 종료 판정 전부 여기. 튜닝 상수도 전부 여기 상단에 모여 있다. |
| `EngageArena.gd` | `class_name EngageArena extends Control` — 시뮬레이터 상태를 그리기만 하는 렌더러. 시네마 밴드 안의 사이드뷰 무대(배경 / 바닥 / 포탑 / 유닛 / 투사체)와 밴드 아래 **참가자 초상화 + 체력 바 스트립**을 담당한다. 종료 사유 배너(`mark_engage_over`)와 결과 대시보드도 여기. |

매니저는 `BattleSim._ready()` 에서 자식으로 붙고 `_bs.engage_phase` 에 잡힌다.
매니저가 소유한 전용 `CanvasLayer`(`ENGAGE_OVERLAY_LAYER = 12`)에 아레나가
붙는다. 이 레이어는 HUD 캔버스(1), `CardSelectOverlay`(10),
`CardTargetingOverlay`(11) 위이므로 무대와 대시보드는 항상 핸드 행과
남아 있는 타게팅 UI 위에 그려진다.

## Trigger flow
1. 플레이어(또는 AI)가 engage 카드(`engage:3` 전투 개시, `engage:4` 완벽한
   기회) 또는 결투(`duel`)를 낸다. `engage:N|exclude_lane` 도 그대로
   동작하지만 현재 이 플래그를 다는 카드는 없다.
2. `CardPhaseManager._effect_engage()` → `EngagePhaseManager.start_engage(...)`,
   `_effect_duel()` → `start_duel(...)`.
3. 매니저가 **들어오기 직전의 페이즈를 `_phase_before` 에 적어 두고**
   `_bs.game_phase = ENGAGE` 로 전환. BATTLE 자동 틱은 멈추고,
   카드 hover/click 과 턴 넘기기도 `CARD_PHASE` 가드 때문에 차단된다.
4. 무대가 열리고 매니저의 `_process` 가 시뮬레이터를 고정 스텝
   (`FIXED_DT = 1/60`, 프레임당 최대 `MAX_STEPS_PER_FRAME = 8` 스텝)으로 굴린다.
5. 종료 판정 → **`END_HOLD_SEC`(2.0초) 유예** → 대시보드(준 딜량 / 받은 딜량 /
   처치 수) → `확인` → 무대 제거, **`phase = _phase_before`**, `on_done` 호출,
   `engage_finished` emit.

복귀 페이즈를 `CARD_PHASE` 로 못박지 않는 이유: 상대 차례
(`CardPhaseManager._run_ai_turn`)는 `game_phase` 를 바꾸지 않고 **BATTLE 안에서**
도므로, AI 가 낸 engage 카드가 끝날 때 CARD_PHASE 로 되돌리면 상대 턴이 끝난
뒤 전장이 작전 단계에 갇힌 채 남는다. 플레이어 카드로 열린 교전은 어차피
`_phase_before == CARD_PHASE` 라 동작이 같다.

AI 플레이도 같은 무대를 탄다. `AiCardPlayer.run_ai_plays()` 는 매 플레이
후 `engage_phase.is_active()` 면 `engage_finished` 를 `await` 한다 — 카드의
effect chain 이 아니라 `is_active()` 로 판정하므로 clause 가 `duel` 인 결투도
정상적으로 기다려진다.

## 시간 규칙 (engage:N → 초)
`N` 은 라운드 수가 아니라 **`N × RealtimeEngageSim.SEC_PER_ROUND` 초**다.
현재 `SEC_PER_ROUND = 3.0` 이므로:

| 카드 | effect | 지속 |
|---|---|---|
| 전투 개시 | `engage:3` | 9초 |
| 완벽한 기회 | `engage:4` | 12초 |
| 결투 | `duel` | 한 쪽 처치까지 (상한 `DUEL_MAX_SEC` 15초) |

제한 시간이 끝나면 **그 프레임에 곧바로 전투가 멈춘다**(후퇴 연출 없음). 그래서
`engage:3` 의 전투 시간은 정확히 9초다. 다만 대시보드는 그 뒤 `END_HOLD_SEC`
(2.0초) 유예를 두고 뜨므로 모달 전체는 약 11초다 — 아래 [종료](#종료) 참고.

## 무대 — 벨트 좌표계
전장의 육각 셀 매핑은 **버렸다**. 파일럿이 전장 어느 셀에 서 있었는지는 배치에
반영하지 않는다 — 자리는 **역할**이 정한다.

```
        ← 팀0 진영 ─────────────┼───────────── 팀1 진영 →
     [포탑]                     │                    [포탑]      ← y=48 (배경 지형)
      225                       │                     1015
        뒷줄(원거리) 앞줄(근접) │ 앞줄(근접) 뒷줄(원거리)        ← y=60~340 (유닛 벨트)
           315        470      620     770       925
```

| 상수 | 값 | 의미 |
|---|---|---|
| `BELT_W` / `BELT_H` | 1240 / 400 | 벨트 전체 크기. x = 진행 방향, y = 얕은 깊이(아래가 가깝다). 유닛은 항상 이 안에 갇힌다 |
| `FRONT_OFFSET` | 150 | 중앙선에서 앞줄까지 (양 팀 앞줄 간격 = 300) |
| `ROW_GAP` | 155 | 앞줄 ↔ 뒷줄 |
| `DEPTH_MARGIN` | 60 | 슬롯이 들어가지 않는 위아래 여백 |
| `SLOT_JITTER_X/Y` | 18 / 14 | 완벽한 일렬을 깨는 흐트러짐 |
| `UNIT_RADIUS` | 40 | 초상화 원 반지름 |
| `STAGE_TOP_EXTRA` | 150 | `stage_rect()` — 벨트 위로 카메라가 비출 수 있는 배경 지형 높이. 유닛 이동 한계(`belt_rect()`)와는 별개 |

`BELT_W` 는 `EngageArena.BAND_RECT`(1032×620→500) 에 통째로 들어가는 크기로
잡혀 있다. **여기를 키우면 카메라 최소 배율이 떨어져 유닛이 잘게 보인다.**

### 진형 배치
팀별로 근접(TANK/FIGHTER/ASSASSIN)은 앞줄, 원거리(SUPPORT/SNIPER)는 뒷줄에
서고, 같은 줄 안에서는 깊이(y)를 균등 분배한다. 이 슬롯이 **개전 시점의**
`anchor_pos` 다 — 첫 공격을 끝내는 순간부터 앵커는 그때그때 서 있는 자리로
갱신되므로 진형은 개전 한 번만 의미가 있다. 한 팀이 전부 원거리면 앞줄은
그냥 빈다.

## ATB — 보이지 않는 게이지
각 유닛은 자기 슬롯에 서서 게이지를 채운다. **게이지는 화면에 표시되지 않는다** —
속도 차이는 "쟤가 더 자주 움직인다"로만 드러난다.

```gdscript
충전 속도 = ATB_FULL × (speed / ATB_REF_SPEED) / ATB_REF_SEC
행동 주기 = ATB_REF_SEC × ATB_REF_SPEED / speed
```

| 상수 | 값 | 의미 |
|---|---|---|
| `ATB_FULL` | 100 | 만충 값 |
| `ATB_REF_SPEED` / `ATB_REF_SEC` | 70 / 1.9 | **speed 70 인 메크가 1.9초마다 한 번 행동한다**는 기준점 |
| `ATB_MAX` | 200 | 저장 상한. 게이지는 **행동 중에도 계속 차므로** 빠른 메크는 한 차례를 끝내자마자 다시 나갈 수 있다(= "가끔 두 번 행동"). 무한정 쌓이지 않도록 2회분에서 끊는다 |
| `ATB_CASTER_HEAD_START` | 0.6 | 교전을 연 시전자는 60% 채운 채 시작 — 선공권 |
| `ATB_START_JITTER` | 0.25 | 나머지는 0~25% 랜덤. 개전 첫 행동이 한꺼번에 터지지 않게 |

`speed` 는 `mechs.csv → MechData.speed → SimulationCore._stats_for →
PilotData.speed` 로 흐른다. 메크가 없을 때(standalone) 폴백은 근접 78 /
원거리 82. **전장(턴제)은 이 값을 읽지 않는다** — 전장 이동은 `move_range` 소관.

실제 메크 speed 범위(40~100)에서의 행동 주기:

| 메크 유형 | speed | 행동 주기 | 9초 교전 행동 횟수 |
|---|---|---|---|
| 탱커 (Aegis-T3) | 44 | 3.02초 | 약 3회 |
| 서포터 (Cleric-P1) | 68 | 1.95초 | 약 4.6회 |
| 격투가 (Striker-B1) | 73 | 1.82초 | 약 5회 |
| 스나이퍼 (Sniper-Q1) | 91 | 1.46초 | 약 6회 |
| 암살자 (Wraith-K1) | 100 | 1.33초 | 약 6.8회 |

## 행동 사이클
```
IDLE ──(게이지 만충)──▶ ADVANCE ──(사거리 진입)──▶ STRIKE ──▶ IDLE
                                                   (그 자리가 새 앵커)
```

| 상태 | 하는 일 |
|---|---|
| `IDLE` | 자기 앵커로 서서히 복원(넉백 복구)하며 게이지 충전. 만충 + 타겟이 있으면 `ATB_FULL` 을 소비하고 ADVANCE |
| `ADVANCE` | 타겟에게 접근. **근접은 `MELEE_REACH`(88px)**, **원거리는 자기 최대 사거리의 `RANGED_APPROACH_RATIO`(0.9) = 270px** 안에 들면 즉시 타격. 이미 그 안이면 움직이지 않고 바로 STRIKE. `ADVANCE_MAX_SEC`(1.8초)을 넘기면 교착으로 보고 이번 차례를 접는다 |

> **사거리 판정에는 `STRIKE_DIST_EPSILON`(0.5px) 여유가 반드시 붙는다.**
> 접근의 정지점은 `target.pos − dir × strike_dist()` 이고 `_step_toward` 가
> 거기에 스냅하므로, 한 차례를 끝낸 유닛은 사거리 **딱 그 거리**에 선다. 그
> 자리에서 다시 잰 거리는 부동소수 오차로 88.0 바로 **위**에 떨어지기 일쑤라
> 여유 없는 `dist <= strike_dist()` 는 거짓이 되고, 유닛은 이미 도착한 정지점을
> 향해 0px 씩 "이동"하다가 `ADVANCE_MAX_SEC`(1.8초) 교착으로만 차례를 접는다 —
> 공격은 한 번도 성립하지 않는다. 헤드리스 실측(근접 1:1, 9초): 여유가 없으면
> 공격 **1회**, 있으면 **10회**(ATB 예측치와 일치). 5v5 에서는 타겟이 계속
> 움직여 정확히 사거리에 서는 일이 드물어 잘 드러나지 않았다 — 정지 상태가
> 되는 1:1 근접에서만 무대가 통째로 얼어붙었다.
| `STRIKE` | 진입 시점에 공격 판정 1회. 모션 홀드(근접 0.26초 / 원거리 0.34초) 동안 대상 앞에 멈춰 있다. 홀드가 끝나면 `_settle()` |
| `DEAD` | 처치됨. 렌더러가 28% 알파로 남긴다 |

이동 속도는 근접 880px/s, 원거리 620px/s. **RETREAT / FLED / RETURN 상태는
없다** — `_clamp_to_belt` 가 매 프레임 전원을 벨트 안에 가두므로 물리적으로도
나갈 수 없고, 무대 안에서도 뒤로 물러나는 행동이 없다.

### `_settle()` — 원위치로 돌아가지 않는다
한 차례(ADVANCE → STRIKE)가 끝나면 `_settle(u)` 가 **지금 서 있는 자리를
`anchor_pos` 로 굳히고** IDLE 로 되돌린다. 접근 교착(`ADVANCE_MAX_SEC` 초과)
이나 타겟 소실로 차례를 접을 때도 같은 경로다. 결과:

- 근접은 때린 자리에 눌러앉으므로 **적진 쪽으로 계속 파고든다**. 원거리도
  270px 안까지 들어간 자리에 남는다.
- `IDLE` 의 앵커 복원 이동(`SETTLE_SPEED_MULT` 0.85)은 진형으로 돌아가는
  이동이 아니고, **넉백을 되돌리는 이동도 아니다** — 넉백은 앵커를 함께 밀기
  때문에(위 [넉백](#넉백-피격-피드백--재접근-거리) 참고) 밀리는 동안 이
  드리프트는 할 일이 없다. 남는 역할은 벨트 클램프 등으로 어긋난 잔차를
  추스르는 것뿐이다.
- 타겟 거리(`_pick_target`)도 갱신된 앵커에서 잰다.
- 헤드리스 실측(5v5, 9초): 팀0 탱커 x 466 → 678, 서포터 303 → 490. 즉 선공한
  쪽이 적진 한복판까지 밀고 들어가 적 뒷줄·포탑 사정권에 오래 노출된다 —
  이것이 미복귀의 리스크다.

### 넉백 (피격 피드백 + 재접근 거리)
명중하면 대상에게 초기 속도가 실리고 `KNOCK_DAMP`(9.0/s)로 지수 감쇠한다 —
근접 `KNOCK_IMPULSE_MELEE`(420) ≈ 47px, 원거리 `KNOCK_IMPULSE_RANGED`(150)
≈ 17px 밀려난다. 벨트 느낌을 위해 세로 성분은 `KNOCK_VERTICAL_SCALE`(0.35)로
눌러 거의 수평으로만 민다. **넉백은 상태와 무관하게 매 프레임 흐른다** —
돌진 중에 맞으면 그만큼 밀린다.

> **밀려난 만큼 앵커도 같이 밀린다** (`_apply_knockback`). 앵커를 제자리에 두면
> `_tick_idle` 의 복원 드리프트(`move_speed × SETTLE_SPEED_MULT`, 근접
> **748px/s**)가 넉백 초기 속도(근접 **420px/s**)보다 빨라서, 맞은 유닛이
> **맞은 그 프레임 안에** 앵커로 되돌아간다 — `_step_toward` 는 6px 안이면
> 목표로 스냅하므로 잔차조차 남지 않는다. 즉 넉백이 화면에 **전혀 보이지
> 않았다**. 밀려난 자리를 앵커로 함께 옮기면 밀린 만큼이 그대로 남고, 그래서
> 때린 쪽은 다음 차례에 그 거리를 다시 좁혀야 한다 — 근접이 매 타격마다
> 파고드는 모션이 여기서 나온다. "밀려난 자리가 새 자리"는 `_settle()` 의
> "공격을 끝낸 자리가 새 자리"와 같은 규칙이다. 되돌리지 말 것.

헤드리스 실측(근접 1:1, 9초): 두 유닛의 거리가 **88 ↔ 138px 사이를 오간다**
(공격 → 넉백 47px → 다음 차례에 재접근 47px). 수비 쪽 유닛이 9초 동안 501px
움직인다 — 예전에는 0px 였다. 빗나가면 넉백도 없으므로 거리는 88 에 그대로
머물고, 그 차례는 제자리 타격이 된다(의도된 동작).

피해나 스탯에 얹히는 효과는 없다 — 넉백이 바꾸는 것은 위치와 그로 인한 재접근
거리뿐이다.

### 타겟 선정 (`_pick_target`)
점수 = `거리 / 존재감`, **낮을수록 매력적**. 빈사(HP 35% 미만)면
`LOW_HP_FOCUS`(0.6) 가중, **아군이 이미 물고 있는 적**이면 인원수만큼
`FOCUS_BONUS`(0.78^n, 하한 0.45) 가중. 이 집중 사격 항목이 없으면 전원이
각자 최근접 적만 때려서 딜이 흩어지고 처치가 거의 안 나온다.
타겟은 **행동을 시작할 때마다** 새로 고른다(예전의 `RETARGET_SEC` 타이머는
행동 단위 모델에서 의미가 없어 삭제).

> **암살자는 예외 — 뒷줄을 노린다** (`dives_backline`). 존재감 어그로를
> 무시하고 원거리 적에게 `DIVE_FOCUS`(0.40) 가중을 준다. **이 분기가 없으면
> 원거리 메크가 교전 내내 단 한 대도 맞지 않는다** — 앞줄이 더 가깝고
> 존재감까지 두 배(4 vs 2)라 모든 근접이 앞줄만 물기 때문. 실측으로 확인된
> 구멍이라 되돌리지 말 것. 대신 다이브한 암살자는 적 진영 한복판에서
> 집중포화를 맞으므로, 이게 암살자의 리스크/리턴이다.

## 포탑 — 참가자가 아니라 **배경 지형**
전장에서는 포탑이 파일럿을 공격하지 않지만, 교전에 가담한 포탑은 **공격한다**.
예전의 "반경 2칸 안의 포탑이 등장하고 사거리원 안이 금지구역" 규칙은 **삭제**
됐다. 지금 규칙은 하나뿐이다:

> **참가 파일럿이 자기 팀 포탑 칸 위에 서 있으면 그 포탑이 교전에 가담한다.**
> 즉 포탑 칸에 있는 적에게 교전을 걸면 그 포탑이 방어에 나선다.

- 가담한 포탑은 **사거리 제한이 없다** — 무대 전체가 사정권이다.
- 포탑도 자기 ATB 를 굴린다. 속도는 `game_config.TURRET_SPEED`(55 →
  2.42초마다 1회), 피해는 `TurretData.atk`.
- 대상은 **포탑에서 가장 가까운 적** — 자기 진영 깊숙이 파고든 유닛이 먼저 맞는다.
- 포탑도 명중 판정을 굴린다. hit 스탯이 없으므로 `TURRET_HIT`(50) 를 쓴다.
- 무대에서 **포탑 HP 는 깎이지 않는다** — 포탑 파괴는 전장 쪽 룰로 남는다.

### 무대 참가자가 아니라 지형 구조물이다
포탑은 벨트 위의 유닛과 같은 층에 서지 않는다. **자기 팀 뒷줄 뒤쪽의 가장 먼
바닥선**(`TURRET_BACK_OFFSET` 90 → x 225 / 1015, `TURRET_BG_Y` 48)에 서고,
`EngageArena._draw_turrets` 가 유닛보다 **먼저**(= 뒤에) `TURRET_BG_SCALE`
(0.58)로 축소해 그린다. 같은 팀 포탑이 둘 이상이면 `TURRET_BG_STEP`(160)
만큼 더 바깥에 나란히 선다.

**카메라는 포탑을 프레이밍하지 않는다**(`EngageArena._focus_positions` 는 생존
유닛만 본다). 포탑까지 담으면 벨트 양 끝까지 프레임에 넣느라 배율이 떨어져
정작 싸우는 유닛이 잘게 보였다. 대신 포탑이 프레임 밖으로 나갈 수 있다 —
싸움이 한쪽으로 쏠리면 반대편 포탑은 안 보이고 포격만 화면 밖에서 날아온다.

이 배치는 두 제약의 균형점이라 **한 값만 따로 만지면 깨진다**:
- 포탑을 벨트 끝(예전 x 130)까지 밀면 카메라 배율(1.2 안팎)에서 **거의 항상
  화면 밖**이다 — 실측으로 확인.
- 포탑을 지평선 너머(y < 0)로 올리거나 크게 그리면 **탑신이 밴드 위로 잘린다**.
  카메라 세로 여백(`CAM_PAD_Y` 40 + `UNIT_RADIUS`)은 유닛 초상화가 거의 다
  먹으므로 유닛 위로 남는 공간이 없다.
- 총구 높이는 `TURRET_BODY_H × TURRET_BG_SCALE` 이고 `_shot_origin` 이 같은
  식을 쓴다 — 크기를 바꾸면 포격선 출발점이 자동으로 따라온다.
- 탑신 색(`TURRET_BODY_COLOR`)은 뒷벽보다 **밝아야** 한다. 어둡게 두면 벽에
  먹혀 사라진 것처럼 보인다.

## 명중 판정 — 피해는 전장과 동일, **명중률은 별개**
```
base   = hit / (hit + evasion)                                 # 전장과 같은 기준값
명중   = randf() < ENGAGE_HIT_MIN + (ENGAGE_HIT_MAX - ENGAGE_HIT_MIN) × base
피해   = attacker.atk        (보호막부터 흡수, 그 다음 HP)
```
피해 공식은 전장(`SimulationCore.roll_hit` / `_apply_damage`)과 공유하지만
**명중 굴림만 교전 전용**이다. 전장보다 훨씬 가까이 붙어 싸운다는 전제라
**최소 80% / 평균 90% / 최대 100%** 구간으로 리맵한다
(`ENGAGE_HIT_MIN = 0.80`, `ENGAGE_HIT_MAX = 1.00`).

| hit vs evasion | base | 전장 | 교전 |
|---|---|---|---|
| 45 vs 55 | 0.450 | 45.0% | **89.0%** |
| 50 vs 50 | 0.500 | 50.0% | **90.0%** |
| 55 vs 45 | 0.550 | 55.0% | **91.0%** |
| 70 vs 30 | 0.700 | 70.0% | **94.0%** |

보정은 단조 증가라 **스탯 우열 순서는 그대로 보존**된다. 전장 명중률을 바꾸고
싶으면 `SimulationCore.roll_hit` 쪽을 건드려야 하며, 두 값은 서로 영향을 주지
않는다. (예전의 `ENGAGE_HIT_LERP` 방식은 base 가 낮을 때 보정폭이 과해
83~88% 로 뭉개졌다 — 지금은 스탯 차이가 명중률에 그대로 1:1 로 실린다.)

### 처리량 — 실측 (헤드리스 5v5 ×8, engage:3 = 9초)
스탯: hp 240/160/90/130/75 · atk 6/14/26/9/24 · speed 44/73/98/72/91 ·
hit 55 / evasion 45 (탱커/격투/암살/서포터/스나이퍼 순, 실제 mechs.csv 값).

| 지표 | 값 (미복귀 + 넉백/사거리 판정 수정 후) |
|---|---|
| 9초 교전당 공격 판정 수 | **평균 40.9회** |
| 9초 교전당 처치(양 팀 합) | **평균 2.75건** |
| 한 명이 준 최대 누적 딜 | 153 |
| 한 명이 받은 최대 누적 딜 | 160 |
| 팀 누적 받은 딜: 근접 vs 원거리 | **3595 vs 1100** (약 3.3:1) |

**처치가 예전(탑뷰·5판에 1건)보다 훨씬 잦다.** 원인은 명중률(80~100%)이 아니라
**딜이 앞줄에 집중되기 때문**이다. 다만 **미복귀 룰이 그 쏠림을 완화했다** —
복귀하던 시절의 근접:원거리 피해비는 9:1(3663 vs 416)이었는데, 지금은 근접이
적진에 눌러앉고 원거리도 270px 안까지 파고들어 남으므로 3.3:1 로 좁혀졌다.

> 이 표는 `STRIKE_DIST_EPSILON` / 넉백-앵커 수정 **뒤에** 다시 잰 값이다.
> 수정 전 수치(처치 2.5 / 근접:원거리 2.9:1)와 거의 같다 — 5v5 는 타겟이 계속
> 움직여 사거리 교착에 잘 빠지지 않았기 때문이고, 그래서 **밸런스를 다시
> 잡을 필요는 없었다**. 교착이 무대를 통째로 얼린 것은 1:1 근접뿐이다.

교전 치사율을 조절하는 노브는 셋이다. **셋 다 교전 전용이라 전장 밸런스를
건드리지 않는다**:
1. **`ATB_REF_SEC`** (1.9) — 전원의 행동 빈도. 올리면 그대로 딜이 줄어든다.
   가장 직접적인 노브.
2. **`ENGAGE_HIT_MIN` / `ENGAGE_HIT_MAX`** (0.80 / 1.00) — 명중률 구간.
3. **`DIVE_FOCUS`** (0.40) — 암살자가 뒷줄로 얼마나 새는가. 1.0 으로 두면
   암살자도 앞줄만 물어서 뒷줄이 다시 무적이 된다.

반면 **피해량(atk 1회분)은 전장 룰과 공유**하므로 손대면 전장까지 같이 움직인다.

## 종료
- **제한 시간 만료**: `elapsed >= duration` 인 프레임에 `finished = true`.
- **한쪽 전멸**: `active_count(team) == 0` 이면 즉시 `finished = true`.
- **저HP**: 아무 일도 일어나지 않는다. 빈사 유닛도 평소와 똑같이 나가 싸운다.
  HP 30% 미만은 무대 위 테두리가 붉게 맥동하는 것(`LOW_HP_RATIO`)으로만
  표시되며 게임플레이 의미는 없다.

### 종료 유예 (`END_HOLD_SEC` = 2.0초)
`finished` 가 서자마자 대시보드를 띄우면 **마지막 처치가 결과창에 먹혀** "방금
누가 죽은 거지?" 가 된다. 그래서 매니저는 종료 판정과 대시보드 사이에
`EngagePhaseManager.END_HOLD_SEC`(2.0초) 유예를 둔다.

- 유예 동안 `_process` 는 `step()` 대신 **`RealtimeEngageSim.step_afterglow(dt)`**
  를 부른다 — 투사체 위치 / `hit_flash` / `swing_t` / 넉백 감쇠만 흐르고 전투
  판정(ATB, 이동, 공격, 포탑, 종료)은 일절 돌지 않는다. `elapsed` 도 멈추므로
  **대시보드의 교전 시간은 실제 전투 시간 그대로**(engage:3 = 9.0초)다.
- 무대는 계속 `_process` 를 돌리므로 카메라도 살아 있다.
- 매니저가 `EngageArena.mark_engage_over(reason)` 로 상단 상태 라벨을 종료
  사유 배너(`교전 종료 — 적군 전멸` / `아군 전멸` / `양측 전멸` / `시간 종료`)
  로 승격시키고 한 번 튕겨(scale 1.18 → 1.0) 시선을 끈다.
- 유예 값을 0 으로 두면 즉시 대시보드로 돌아간다.

### 전장 상태 반영
- 데미지는 `PilotData.hp` / `.shield` 에 **직접** 적용된다. 교전이 끝나면
  전장에 그대로 반영된다.
- 처치 → `_bs.mark_pilot_dead(pilot)`. 전장과 같은 사망 경로라 리스폰 턴
  스케일링(`respawn_turns_now()` = 5 + 경과 턴/10)과 전사 연출이 무대
  처치에도 그대로 걸린다.
- **`grid_pos` 는 건드리지 않는다.** 살아남은 파일럿은 원래 셀에 그대로 남는다.
  저HP 파일럿은 작전 단계 종료 시 `RecallSystem.process_phase_end_recalls()`
  의 HP 임계 복귀가 어차피 본진으로 데려간다.

## 화면 구성 (`EngageArena`)
```
EngageArena (Control, 풀스크린, MOUSE_FILTER_STOP)
├─ dim        ColorRect 풀스크린 (검정 α 0.86)   ← 무대 밖을 눌러 준다
├─ 타이틀(240) / 타이머(296) / 남은 시간 바(368) / 상태·배너(390)
├─ _clip      Control BAND_RECT, clip_contents = true   ← 여기서 잘린다
│   └─ _world DrawProxy(Node2D)  position/scale = 카메라
│        └─ 데미지 팝업 Label 들 (벨트 좌표계)
├─ _hud       DrawProxy(Node2D) 화면 좌표계 — 밴드 테두리 · 남은 시간 바
├─ _roster    DrawProxy(Node2D) 화면 좌표계 — 하단 초상화 + 체력 바
├─ 아군/적군 헤더 + 참가자 이름 Label 들
└─ 대시보드 Panel (종료 시)
```

### 시네마 밴드
`BAND_RECT`(24, 440, 1032×500) **한 사각형 안에서만** 무대가 보인다. 그 밖
(전장 · 핸드 행 · HUD)은 풀스크린 딤으로 눌린다. 벨트(1240×400)가 가로로
꽉 차고 세로로 약간 여유가 남는 비율이다.

**왜 `_draw()` 를 자기 자신에 안 쓰는가**: Control 은 자기 그림을 먼저 그리고
그 위에 자식을 그린다. 딤 ColorRect 가 자식이므로 자기 `_draw` 로 그린 무대는
딤 **아래**에 깔려 통째로 어두워진다. 딤보다 뒤에 붙은 프록시 노드에 그려야
"무대 밖만 딤드"가 성립한다.

**왜 `DrawProxy` 가 Control 이 아니라 Node2D 인가**: Control 은 DRAW 통지마다
자기 크기로 `custom_rect` 를 다시 박는다. 크기 0 인 Control 은 빈 사각형으로
**컬링되어 `_draw` 안의 그림이 통째로 사라진다**(자식 Label 은 자기 rect 가
있으니 멀쩡히 보여서 더 헷갈린다). Node2D 는 실제 draw 커맨드에서 rect 를
잡으므로 카메라 변환(scale/position) 아래에서도 안전하다.

### 사이드뷰 배경
`y = 0` 이 지평선이다. 그 위로 `BACKWALL_H`(120) 만큼 **바닥보다 어두운 뒷벽**
띠와 155px 간격 세로 기둥이 깔리고, 더 위는 하늘 그라디언트다. 바닥은 위(먼
곳) → 아래(가까운 곳)로 밝아지고, 중앙선 기준 좌우에 팀색 틴트(`SIDE_TINT_A`
0.16)가 얹혀 진영이 한눈에 보인다. 뒷벽을 바닥보다 어둡게 잡는 것이 사이드뷰
깊이감의 핵심이다 — 같은 밝기로 두면 지평선이 사라져 평면으로 읽힌다.

유닛은 **깊이(y) 순으로 정렬해서** 그린다. 아래쪽(가까운) 유닛이 위에 겹친다.
시뮬레이터의 `units` 배열은 팀별 순서라 그대로 그리면 원근이 깨진다.
초상화 원은 발밑(`pos`)에서 `UNIT_LIFT`(42px) 위에 뜨고, 발밑에는 납작한
타원 그림자가 깔린다. 투사체도 발이 아니라 몸통 높이에서 출발/착탄한다.

### 카메라
`_update_camera()` 가 매 프레임 **생존 유닛 전원**의 바운딩 박스를 프레이밍한다.
**참가 포탑은 넣지 않는다** — 위 [포탑](#무대-참가자가-아니라-지형-구조물이다)
참고.

| 상수 | 값 | 의미 |
|---|---|---|
| `_cam_min_zoom` | 런타임 계산 ≈ **0.83** | 벨트 전체(1240×400)가 밴드에 딱 들어가는 배율. `belt_rect()` 기준 |
| `CAM_MAX_ZOOM` | 1.55 | 유닛이 뭉쳤을 때의 상한 |
| `CAM_PAD_X` / `CAM_PAD_Y` | 80 / 40 | 바운딩 박스 바깥 여백(벨트 px). `UNIT_RADIUS` 는 별도로 더해진다 |
| `CAM_POS_RATE` / `CAM_ZOOM_RATE` | 4.0 / 2.6 | 지수 감쇠 계수(1/s) |

`_clamp_cam_center()` 가 매 프레임 카메라를 **`stage_rect()`**(벨트 + 위쪽
`STAGE_TOP_EXTRA` 150 의 배경 지형) 안에 가둔다 — **뷰는 그려진 것이 없는 곳을
비추지 않는다.** 클램프 기준이 `belt_rect()` 가 아닌 이유는 지평선 근처의 배경
지형까지 화면에 들어올 수 있어야 하기 때문이고, 최소 배율은 여전히
`belt_rect()` 로 잡는다(배경까지 담게 하면 유닛이 잘게 보인다). 뷰가 무대보다
넓은 축은 그냥 중앙에 고정한다. `setup()` 은 첫 프레임을 보간 없이 스냅한다.

데미지 팝업은 `_world` 의 자식이라 카메라를 따라 움직이고 뷰 밖에서 잘린다.
대신 월드 스케일까지 먹으므로 글자 크기가 배율에 휘둘리지 않도록 `1/zoom` 을
되먹여 화면상 크기를 고정한다.

### 하단 초상화 스트립
밴드 아래에 **아군(1010) / 적군(1292)** 두 줄로 참가자 원형 초상화(150px)가
깔리고 그 아래에 체력 바(168×18, 보호막은 남은 체력 오른쪽에 이어 붙음),
그 아래에 이름 라벨이 붙는다. 5명 미만이면 가운데 정렬된다.

- 테두리는 팀색. **행동 중(ADVANCE/STRIKE)이면 금색으로 승격**된다 — 지금

- 처치되면 뒤판이 붉어지고 알파가 35% 로 떨어지며 이름에 `(처치)` 가 붙는다.
- 초상화 / 체력 바는 `_roster` 프록시가 매 프레임 다시 그린다. Label 노드는
  이름뿐이라 `_refresh_names()` 만 돈다.

## 참가자 수집 (변경 없음)
시전자 셀 + 인접 6칸(반경 1 육각). 시전자는 항상 포함. 양 팀의 생존
파일럿이 그 7칸 안에 있으면 참여한다. 정글러/레인 파일럿의 교전 스코프
구분은 여기서 적용되지 않는다 — engage 는 그 경계를 명시적으로 넘는다.

### `exclude_lane` 플래그 (현재 이 플래그를 쓰는 카드는 없음)
이 플래그를 달고 있던 **교전(id 4) 카드는 `cards.csv` 에서 제거**되어, 지금
카드 풀에는 이 플래그를 세우는 카드가 하나도 없다. 플래그 자체는
`CardPhaseManager` → `CardTargetingOverlay` 프리뷰 → `start_engage` 까지
그대로 파싱·처리되므로, 앞으로 어떤 카드든 `engage:N` 절에 `|exclude_lane`
을 붙이면 다시 살아난다.

```gdscript
# inclusion rule under exclude_lane:
p.is_guerrilla OR _bs.neutral_zone_cells.has(p.grid_pos)
```

## 대시보드 통계
PilotData 를 키로 하는 dict:
```gdscript
{ "dealt": int, "taken": int, "kills": int }
```
`dealt` / `taken` 은 실제로 깎인 양(`shield_absorbed + hp_dmg`). 빗나감은
집계되지 않는다. 포탑에게 맞은 딜은 `taken` 에 잡히지만 `dealt` 는 아무에게도
귀속되지 않는다.

## Presence stat
`presence` 는 **타겟 어그로 가중치**로만 쓰인다(높을수록 자주 표적이 된다).
`mechs.csv → MechData.presence → SimulationCore._stats_for → PilotData.presence`.
메크가 없을 때(standalone) 기본값은 근접 4 / 원거리 2. 암살자는 이 가중치를
무시한다 — 위 [타겟 선정](#타겟-선정-_pick_target) 참고.

## 헤드리스 검증
`RealtimeEngageSim` 은 `RefCounted` 라 노드/프레임 없이 돌릴 수 있다.
BattleSim 인스턴스만 하나 있으면:
```gdscript
var sim := RealtimeEngageSim.new()
sim.setup(bs, caster, team0_pilots, team1_pilots, 9.0, false)
while not sim.finished:
    sim.step(1.0 / 60.0)
    sim.popups.clear()   # 렌더러가 없으면 아무도 비워 주지 않는다
```
⚠ 두 가지 함정:
1. standalone BattleSim 은 `pilots.csv` 로 폴백하는데 그 `atk` 는
   160/300/500 이라 한 대에 즉사한다. 밸런스를 보려면 PilotData 에
   mechs.csv 급 스탯(hp 75~240 / atk 6~30 / speed 44~100)을 찍고 돌려야 한다.
2. `BattleSim.tscn` 인스턴스화는 **`SceneTree._initialize` 안에서 하면 매달린다**.
   던져 놓을 `Node` 씬을 하나 만들어 `_ready` 에서 `await process_frame` 뒤에
   붙일 것. 렌더까지 보려면 `--headless` 를 빼고 창 모드로 띄운 뒤
   `get_viewport().get_texture().get_image().save_png(...)` 로 찍는다.
